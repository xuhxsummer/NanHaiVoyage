## 1) Combat AI: lock chase vs flee-at-half
Bug: `updateCombat` comment says "Stationary, no retaliation chase" — pirate only turns/fires in range, never sails toward player. `lockPirate()` sets `combatLock` but does not enable chase (`pirateChase` stays false).

Desired rules:
- **Pirate + warship**, while player has them locked (`combatLock` / warship lock equivalent): **chase the player and attack** (move toward player + fire in range). Setting lock must set chase on.
- **Merchant** (legacy merchant + traders): when hit / hostile — **flee while returning fire** (already partly there; keep/fix flee+fire). Merchants never chase.
- **Pirate + warship** when **HP ≤ 50%** of max: switch to **flee while firing** (mirror merchant flee: sail away + keep shooting). Above 50% and locked → chase.
- Unlocked pirate in aggro range may still fire if already in combat range, but **chase requires lock** (user: 海盗和战船在我锁定之后会追着我打).

Files: `GameState.updateCombat`, `lockPirate`, warship AI (`updateWarship` / `warshipHostile`), trader/merchant flee paths.

## 2) Mutual collision push (ships stick)
0.28.23 `separatePlayerFrom` only moves the **player**; NPC stays put → sticky overlap. `ensurePirateSeparation` is mutual but merchant/trader/warship path is one-sided.

Fix:
- On hull overlap, **both** bodies move apart along contact normal every frame (bounded step, e.g. ≤6–12 units/step), split ~45/55 or by relative size.
- Apply to pirate, merchant, traders[], warships[].
- After impact/ram, visible rebound: I get pushed back a bit, they get pushed the other way — not glued.
- Keep ram damage/cooldowns; this is positional physics.

Files: `GameState.separateLiveShips` / `separatePlayerFrom` / `ensurePirateSeparation` / `updateShipImpacts`.

## 3) Sink / fail popup: close = restart
`failurePage()` offers 读取存档 / 重新开始, but frame close (`closePopup`) sets `dismissedFail=true` and leaves `g.failed` with hull 0 → ship unoperable.

Fix:
- Top-right **X / 关闭** on 船只已沉没 / 航程失败 must call the same path as **重新开始** (or force reopen fail until player picks 重新开始 / 读档 — user said 应该重新开始, so prefer **close ≡ restartNewGame**).
- Do not leave a failed voyage with dismissed overlay and 0 durability.

Files: `VoyageScreen.failurePage`, `closePopup` when `Overlay.FAIL`, `restartNewGame`.
