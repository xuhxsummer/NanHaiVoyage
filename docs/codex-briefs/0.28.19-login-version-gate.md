## Goal (user UX)
On **every** visit to LoginScreen:

1. Bottom of login page: a **progress bar** with a small **ship icon** sitting on/above the fill (use an existing ship texture under `android/assets/textures/ships/`, e.g. `ship_小商船.png` or smallest clear icon — scale tiny).
2. While checking version: hide or disable account/password form (or keep it invisible until gate opens). Show status text like「正在检查版本…」.
3. Progress bar animates during check (indeterminate or 0→~90 while waiting is OK).
4. **If already latest** (or check fails offline): finish progress to 100%, then **reveal** login account/password (+ register) UI. Do not block forever on network failure — treat failure as “allow login” after a short timeout (~5–8s) with toast「网络不佳，先进入」.
5. **If newer version on GitHub Releases**: show existing「发现新版本」update dialog (full APK download via current UpdateChecker). Do **not** reveal login form until user declines/later, OR keep form hidden while update is mandatory-feel — user said 有新版则弹出更新; allow「稍后」to reveal login (match current decline behavior).
6. Check must run **every time** LoginScreen is shown — remove / bypass AndroidUpdateChecker’s once-per-process `checked` latch (or reset it on each `checkForUpdate()` from login).

## Implementation hooks
- `LoginScreen` — gate form visibility; add bottom progress + ship actor.
- `UpdateChecker` interface — extend Listener with e.g. `onCheckFinished(boolean updateAvailable)` or `onUpToDate()` so UI knows when to reveal form. Keep existing `onUpdateAvailable` / download progress for the modal.
- `AndroidUpdateChecker` — always re-check on each `checkForUpdate()`; still silent on parse errors but **must callback** so UI can unblock.
- Desktop/lwjgl FakeUpdates: implement new callbacks so smoke/desktop doesn’t hang.

## Out of scope
Differential/patch downloads, Play Store, sea-map assets, audio changes.

## Success
Every login: bottom ship progress → version check → latest shows form / newer shows update dialog; Release **v0.28.19**.
