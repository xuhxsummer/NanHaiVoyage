# NanHaiVoyage 0.28.15 — Main-quest card opens dialogue (common mobile VN style)

## Model
`gpt-6-astra` **high**, `/fast` **off**, never luna. Visible Codex in `~/shipgame`.
First reply: quota OK or usage-limit/reset.

## User intent
Main line **is** the story. Tapping the HUD quest card should open **dialogue interaction** like common Chinese mobile RPGs (bottom speaker box, name tag, tap to advance), NOT jump straight into the full quest list UI.

Today (0.28.14): card click → `toggleQuestOverlay()` (full 任务 panel). Story text only lives as `QuestDef.story` in that panel detail.

## Goals

### 1. Tap 任务卡 → story dialogue overlay
- Wire `VoyageHud` quest-card callback in `VoyageScreen.buildHud` (~L350): for card 0 (current 主线), open a **dialogue player** instead of (or before) the quest list.
- Card 1 (下一程) may show a short “尚未解锁 / 前序领奖后开启” line, or the next quest’s preview dialogue if unlocked — pick the clearer UX.
- Keep rail button「任务」opening the existing full quest log (list + claim/nav) unchanged.

### 2. Dialogue UI (no new art packs)
Scene2D, Tang/大唐海贸 chrome (parchment + gold frame, reuse QuestUi / VoyageHudChrome / login panel styles):
- Semi-dim full-screen catcher
- Bottom dialogue panel ~ full width, ~220–280px tall
- Speaker name plaque (e.g. 老掌柜 / 船医 / 旁白 / 你)
- Body text (wrap, readable on phone)
- Hint: 「点击继续」; tap anywhere on panel/dim advances one line
- Skip / 关闭 button to dismiss without forcing finish
- Optional: after last line, show one primary button 「前往」/「领奖」/「知道了」 that mirrors quest actions when relevant (nav if targetPort/Island, claim if complete+unclaimed, else close)

### 3. Dialogue script data — YOU write / split
For each of the 19 quests (0–18), turn existing `story` (+ optional flavor) into **2–5 spoken lines** with speakers. Prefer:
- Store as `String[][]` or small struct on `QuestDef` (speaker, text), OR `android/assets/text/quest-dialogue.json` / `.md` loaded once
- Chinese, Wu Zhou / 《南海见闻录》 tone, short lines (phone-friendly)
- Reuse / expand 0.28.14 story copy; do not delete narrative flavor from quest detail

### 4. When dialogue auto-plays (lightweight)
- First time a quest becomes the active 主线 (unlock / after previous claim): auto-open dialogue once per quest id (persist flag on GameState or Preferences)
- Manual reopen anytime via tapping the 主线任务卡
- Do NOT block sailing controls forever; world may pause lightly while dialogue is open (or keep sailing — prefer pause input for dialogue only)

### 5. Regression
- Claim / progress / unlockAfter chain unchanged
- Auto-sail ignore pirates from 0.28.14 still intact
- Font `ui-chars.txt` must cover any new glyphs used in dialogue
